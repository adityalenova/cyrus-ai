Introduction

cyrus.ai is a static multi-page site: plain HTML, CSS and JavaScript, no framework, no build step. The catalog lives in one file (data.js) generated from the GitHub API. Pages render it client-side; repo detail pages additionally call the live GitHub API when you open them.

data.js      — 528 repo records (stars, forks, license, language, topics…)
site.js      — shared chrome: nav, footer, ⌘K palette, auth, tilt/reveal
home.js      — hero code-panel typing, org marquee, feature visuals
browse.js    — shelves & grid directory
repo.js      — per-repo profile pages with live API enrichment
pages.js     — sponsors board, submit queue, forum, community stats

The dataset & refresh

The snapshot is produced by generate.mjs, which reads raw GitHub topic-search dumps (.rawdata/) for topics like agent-skills, claude-code, cursorrules, mcp-server and agents-md, dedupes by repo name, classifies each repo into one of the five shelves (with a curated override map for well-known projects), filters to repos with a description and ≥25 stars, and caps each shelf. Re-running it regenerates data.js in seconds:

node generate.mjs
# → data.js v2: 528 repos {"skills":220,"mcp":150,"tools":80,"agentsmd":50,"cursor":28}

Star counts in cards are frozen at snapshot time (2026-10-02); repo pages show live values whenever the API answers, and label which is which.

Repo pages & live API

Opening repo.html?id=owner/name renders the snapshot record immediately, then fires unauthenticated requests to api.github.com for:

  • /repos/{id} — refreshes stars, forks, open issues and the community pulse;
  • /repos/{id}/contributors?per_page=12 — the avatar wall with real commit counts;
  • /repos/{id}/languages — the language breakdown bar.

Any request that fails (usually the 60 req/h unauthenticated limit) silently falls back to snapshot data, and the page keeps the honest “from the snapshot” label.

Search & filters

⌘K / Ctrl-K (or /) opens the command palette on every page. It searches names, descriptions, tags and languages across all 528 repos, ranked by stars. Category chips on browse filter shelves and grid; deep links like browse.html#mcp open a shelf pre-filtered.

Listing a repository

submit.html parses your URL, fetches /repos/{id} live, auto-detects the shelf from your topics and description, and queues the listing with a verified/unverified badge. In this demo the queue is stored in your browser's localStorage (agenthub.submissions); in production it posts to a review endpoint backed by the same enrichment.

Authentication today

Sign-in (GitHub / Google / guest) creates a local demo session in localStorage — enough to exercise saved repos, submissions and forum posting. No credentials are transmitted anywhere. Production OAuth (GitHub App + Google) replaces the prompt step behind the identical buttons; the session shape ({name, provider}) stays the same.

Embedding the data

data.js is a flat, well-commented array — REPOS records carry cat, repo, stars, forks, issues, lang, license, updated, home, url, desc, tags. Import it anywhere, or hit the GitHub API yourself the same way the detail pages do.

Roadmap

  • Weekly automated snapshot + changelog of risers/fallers;
  • Real OAuth + accounts, so saved shelves travel with you;
  • Submit flow → backend review queue → one-click accept;
  • Install counts (“how many AGENTS.md reference this skill”);
  • Per-shelf GitHub Discussions replacing the demo forum.
